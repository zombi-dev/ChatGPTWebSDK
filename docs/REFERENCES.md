These are reference snapshots; an older client does not establish the current ChatGPT protocol. No source from these additional repositories was copied into the SDK. The conversation transport, stream parser, browser lifecycle, authentication extension and captured-operation mappings are implemented in this repository.

The original [Simatwa/WebChatGPT](https://github.com/Simatwa/WebChatGPT) is an older protocol reference. The supplied HAR provides the observed modern request shapes, project/temporary flags, file upload sequence and stream variants. [HAR_COVERAGE.md](HAR_COVERAGE.md) records those mappings without private values.

The replacement's public types come from the separately licensed, vendored [official OpenAI .NET SDK](https://github.com/openai/openai-dotnet), pinned to 2.14.0; its license is retained. The [official OpenAPI repository](https://github.com/openai/openai-openapi) is the source for the separate 353-operation REST catalog. This does not imply those platform endpoints are available on ChatGPT web.

Browser implementation uses Chromium's [unified headless mode](https://developer.chrome.com/docs/automation-and-testing/headless), the browser-level [SystemInfo DevTools domain](https://chromedevtools.github.io/devtools-protocol/tot/SystemInfo/), and the browser pinned by [Microsoft.Playwright](https://playwright.dev/dotnet/docs/browsers). Hardware availability is observed through Chromium's compositing status; software mode disables GPU rendering/compositing. Browser bundles retain their driver, Node and Chromium license notices.

## v1.6.0 OAuth reference and adapted implementation

[evanzhoudev/openai-oauth](https://github.com/EvanZhouDev/openai-oauth) was cloned and reviewed at revision [`9079e62840a7`](https://github.com/EvanZhouDev/openai-oauth/tree/9079e62840a7f4b19114cb8f4bb0009b5bcf1773) on 2026-10-11. Unlike the original 13 references above, parts of its Apache-2.0 design and normalization are adapted in the C# OAuth module. Upstream [LICENSE](../third_party/openai-oauth/LICENSE), [NOTICE](../third_party/openai-oauth/NOTICE) and the [adaptation record](../third_party/openai-oauth/ADAPTATIONS.md) are retained and packaged.

Reviewed `packages/core/src/runtime.ts`, `state.ts`, `sse.ts`, `models.ts`, `images.ts`, the local credential loader, client adapter, proxy handlers and shared extension flow. Adopted PKCE, explicit credential-file import, serialized refresh/rotation, account and FedRAMP claims, Codex Responses normalization, streaming and non-streaming compatibility, function-tool translation, model discovery/defaults/Responses Lite, and bounded local history expansion, and direct image generation/editing normalization. Added stricter callback validation, isolated cache lookup, atomic writes and terminal-stream checks.

The React sign-in UI, browser IndexedDB store, Node CLI daemon and extension handshake are separate application flows; they are not dependencies of the C# SDK. Existing web image/upload management remains on the web backend; the OAuth image client uses the separate Codex image endpoints. The OAuth backend passes supported Responses tools through but does not invent website conversation IDs or automatically replace a failed web generation with a different backend. The account's upstream permissions and model access remain authoritative. See [OAuth usage](OAUTH.md) and [OpenAI Codex authentication](https://developers.openai.com/codex/auth).

## v1.7.0 HTTP Sentinel reference

[realasfngl/ChatGPT](https://github.com/realasfngl/ChatGPT) was cloned and reviewed at [`a9544579d649fce7796c3e60460a975bfae7d5eb`](https://github.com/realasfngl/ChatGPT/tree/a9544579d649fce7796c3e60460a975bfae7d5eb) on 2026-10-12. No license file was found. The SDK contains an independently written C# protocol implementation; the Python source and its dependencies are not vendored or required.

Reviewed `wrapper/chatgpt.py`, `reverse/challenges.py`, `reverse/decompiler.py`, `reverse/parse.py` and `reverse/vm.py`. The unmodified client failed because its external geolocation HTML parser was outdated. A private parser adapter allowed its anonymous HTTP conversation to complete. The C# implementation instead reads location/build metadata from the same ChatGPT page, avoids both external location requests, caches metadata and HTTP connections, serializes fixed proof fields once and interprets bounded symbolic instructions directly instead of generating JavaScript and parsing an AST. It rejects unsupported instruction formats and runs no downloaded code.

The reference's brittle conversation-ID extraction and incomplete SSE handling were not adopted. Existing SDK full-message/patch decoding, per-user remote conversation bindings, temporary/project context, MCP loops and uncertain-send reconciliation remain shared by all web modes. Authenticated HTTP generation and append-only follow-ups are independently verified; the reference's anonymous success alone is not used as evidence of signed-in support. See [verification](VERIFICATION.md).

## v1.7.1 document and ZIP reference

The [lesleyxyz/ChatGPT `patch-1` fork](https://github.com/lesleyxyz/ChatGPT/tree/652e434190f4fd6277569a50491542d0765c316e) was cloned and reviewed at `652e434190f4fd6277569a50491542d0765c316e`, against upstream `a9544579d649fce7796c3e60460a975bfae7d5eb`. Four fork-only commits add general file uploads, authorization and wrapper refactoring; it misses three later upstream commits. The VM, proof solver and parser source files are identical between those tips. No license file was found; no fork source was copied or vendored.

The independently implemented C# change takes the protocol distinction between document metadata attachments and image pointers, and the `my_files`/`ace_upload`/`multimodal` upload categories. The signed-in backend accepted both PDF and ZIP upload/processing flows and read their file contents in live verification on 2026-10-13. The C# implementation retains correct MIME types, case-insensitive filenames, real streaming, per-user ownership, cached history and scoped credentials. The fork's broken image-call signatures, global authorization headers on external hosts, PNG labeling of all images, anonymous-only routes and unlimited response buffering were not adopted.
